# Agent 驱动的自动化投研系统

根据 [技术设计](TECHNICAL_DESIGN.md) 实现的美股投研初稿生成器：SEC/XBRL 数据、Google 搜索结果、确定性指标计算、CrewAI 三 Agent、阶段检查点与来源报告，以及三页前端。默认由 SerpApi 获取搜索结果，OpenAI 分析；Gemini Google Search Grounding 可选。

## 启动

要求 Python 3.11+、Node.js 20+。先复制 `.env.example` 为 `.env`，填写有效的 `SEC_USER_AGENT`（组织名称及联系邮箱）、`OPENAI_API_KEY` 和 `SERPAPI_API_KEY`。示例默认使用 OpenAI Agent + SerpApi Google 搜索；将 `CREWAI_MODEL` 改为你的账户可用模型。启动命令显式读取 `.env`；不要提交此文件。

```bash
uv sync --extra dev
uv run --env-file .env uvicorn invest_research.api:app --host 127.0.0.1 --port 8001 --reload
```

另开终端启动页面：

```bash
cd frontend
npm install
npm run dev
```

页面地址为 `http://127.0.0.1:5173`；Vite 将 `/api` 请求代理到 `http://127.0.0.1:8001`，避免与其他项目的 8000 端口冲突。前端端口被占用时会报错，不会静默切换地址。CLI 同步运行：`uv run --env-file .env invest-research "Apple Inc." --ticker AAPL`。

依赖安装完成后，也可以在项目根目录运行 `bash scripts/start-local.sh`，一次启动前后端。脚本会先检查两个端口，任何一个被占用都会退出，不会停止其他项目。按 Ctrl+C 关闭本次启动的服务。没有 `.env` 时仍可访问页面及历史记录，但生成报告需要先填写上述配置。

## 选择 Agent 模型与搜索服务

三个 CrewAI Agent 共用 `CREWAI_MODEL`。搜索服务由独立的 `SEARCH_PROVIDER` 选择，与 Agent 模型可以自由组合。项目显式安装 Gemini 提供方依赖和 OpenAI SDK；当前锁定的 CrewAI 版本没有单独的 `openai` extra。

| 用途 | `.env` 中的配置 | 所需密钥 |
| --- | --- | --- |
| OpenAI Agent（示例默认） | `CREWAI_MODEL=openai/<模型ID>` | `OPENAI_API_KEY` |
| Gemini Agent | `CREWAI_MODEL=gemini/<模型ID>` | `GEMINI_API_KEY` |
| SerpApi Google 搜索（默认） | `SEARCH_PROVIDER=serpapi` | `SERPAPI_API_KEY` |
| Gemini Google Search Grounding | `SEARCH_PROVIDER=gemini_grounding` | `GEMINI_API_KEY` |

SerpApi 是第三方 Google 搜索结果服务，不是 Google 官方 API。它返回标题、链接和搜索摘要；系统把结果及来源 ID 传给研究 Agent，并在 `01_search_results.json` 保留规范化的检索中间产出。搜索摘要不是网页全文或已核实事实，重要信息应由分析师打开原文复核；财务数值以 SEC/XBRL 为准。SerpApi 请求使用 `before:` 限定截止日期，但历史搜索结果不能保证完全可复现。SerpApi 接口说明见 [Google Search API](https://serpapi.com/search-api) 与 [Organic Results](https://serpapi.com/organic-results)。

OpenAI 可选参数包括 `OPENAI_API_MODE`（`completions` 或 `responses`）、`OPENAI_TIMEOUT`、`OPENAI_MAX_RETRIES`、`OPENAI_MAX_COMPLETION_TOKENS`、`OPENAI_REASONING_EFFORT`、`OPENAI_ORGANIZATION` 和 `OPENAI_PROJECT`。只为所选模型设置它支持的参数。`OPENAI_BASE_URL` 仅在明确要使用自定义 API 端点时填写；它会改变请求发往的地址。留空时使用提供方默认端点。模型 ID 和可用参数应按当前账户及提供方文档确认。

## 限制与评测

- 需要所选搜索服务与 Agent 模型的密钥；SEC 访问需要有效 User-Agent。没有这些配置时任务明确失败。默认的 OpenAI + SerpApi 组合不需要 Gemini 密钥。
- 当前实现优先覆盖美国非金融公司、US GAAP 标准概念。数据缺失会进入“需人工复核”，不会计算成成功。
- 财报原件如果是 PDF，可用 `extract_pdf` 获得带页码的文本；数值仍以 SEC XBRL 为准。扫描 PDF 暂无 OCR。
- 研究阶段已记录每项业务、进展和风险结论的原文证据并校验引用真实性；证据是否充分支持结论仍由模型复核，最终报告的语义准确性需要人工评审与预设样本评测验证。
- 设计文档中的 >95% 成功率和效率提升是验收目标，尚未完成 200 次在线评测。

运行本地测试：`uv run pytest`；前端构建：`cd frontend && npm run build`。

## 处理“需人工复核”与补充资料

任务详情页的“资料复核与补充”会展示具体缺口、所属阶段和处理建议，也兼容历史报告。缺口分为两类：

- **待补齐**：影响核心结论的证据或必需指标缺失，会阻止自动校验通过。历史 `gaps` 保守保留为这一类，不自动降级。
- **分析局限**：未开展的扩展分析等范围限制，以 `limitations` 保存并写入报告，不单独阻断通过。分类由 Agent 根据结论与证据判断，仍需人工核验。

点击“补充资料 / 重新分析”，可以粘贴相关原文、填写来源链接和发布日期，最多累计保留五份。资料发布日期不得晚于原任务截止日期。用户摘录会标为待核验资料，不会替代 SEC/XBRL 财务数值验证；页面不会自动抓取这些链接。不添加资料也可以重新检索。

重新分析创建独立的新版本，沿用已确认的公司身份、研究范围和既有补充资料，从信息搜集开始重新运行，原报告及产出保留。新版本可返回上一版本。此操作会重新调用搜索服务和模型。API 为 `POST /runs/{id}/reanalyze`，需要 `Idempotency-Key`，请求体为 `{"supplements": []}` 或包含 `title`、`url`、`published_at`、`content` 的资料数组。

信息搜集现会下载截止日期前最新的年报和季报正文，提取 HTML（过滤脚本和隐藏 XBRL）或 PDF 文本，保存正文、内容摘要及来源哈希，并向研究、分析 Agent 提供片段和按关键词读取工具。正文读取失败仍要求复核。搜索结果按公司名称/代码做相关性初筛，不足时追加一次定向检索；初筛不是事实核验。网页来源不足会披露为局限，关键结论仍须有正文证据。

校验产出保留原 `gaps`（指标 ID 列表）以兼容旧调用，新增 `issues` 汇总研究、分析、指标及其他校验问题，并携带 `stage`、`severity`、`message`、`action`。不要仅根据 `gaps: []` 判断报告是否完整。

### 叙述数字校验

撰写 Agent 与最终报告使用相同的数值一致性校验：正文数字须紧跟单位及唯一指标引用，例如 `2025年营收同比为6.43%（metric_id: 营收同比-2025）`。示例仅说明格式，实际数值来自当前任务 `02_metrics.json` 中 `verified` 的指标。代码核对指标名称、明确写出的期间、数值、正负号和单位，支持美元/万美元/百万美元/亿美元/十亿美元换算；百分比与百分点不互换。

普通数值按展示的小数位允许半个末位单位的舍入误差；“约为/接近”还须满足相对误差不超过百分之一（零附近使用很小的绝对容差）。因此真实比率为 0.995286 时，`经营现金流量与净利润比率接近于1（metric_id: 经营现金流/净利润-2025）` 可以通过。每个数值单独引用一个指标，不接受一组指标对多个数字的模糊引用。明确的前后期“上升至/下降至”等比较须引用同口径、按时间先后排列的指标，代码检查变化方向。

这是一套有边界的格式与一致性校验，不是通用自然语言事实核验：未支持的写法、非指标数字和派生百分点变化仍需改写；纯定性断言及因果解释不由数值检查证明。已知来源 ID、指标 ID 和 SEC 表单名称中的数字仍不作为正文数值处理。

来源 ID 使用包含 XBRL 来源在内的完整来源目录校验。对 `H20`、`H200`、`GB300` 这类型号，仅当其在前序研究结论和已下载财报正文中都原样出现时，才豁免型号内的数字；这不代表相关业务结论已获得事实核验。未知型号、未知来源及未引用指标的金额和比例仍须通过原有校验。撰写与最终报告使用相同规则。

每次撰写校验将结构化草稿和问题字段、数字片段保存到 `03_writing_validation.json`，可通过任务产物接口查看；失败草稿不会成为成功检查点。代码修改后需重启后端，已有失败任务重试时复用研究和分析检查点。

### 自动补证据与撤回结论

任务详情页提供两个直接操作，均创建独立版本：

- **自动补证据并重新分析**：重新获取财报、从完整正文检索相关片段，结合上一版缺口进行第二轮研究复核。无需手动重复粘贴已经存在于财报中的材料。
- **撤回无依据结论并重新分析**：复核并纠正结论；无法核实的非核心结论会删除并记录在分析局限中。核心业务、风险覆盖、财报下载失败和必需财务指标缺失仍阻断通过。

API 请求新增可选 `mode`：`complete_evidence`（默认）或 `remove_unsupported`；例如 `{"supplements": [], "mode": "remove_unsupported"}`。历史记录不会被改写，需创建新版本使用新流程。

每次新研究增加一次模型复核调用，因此耗时和费用会增加。复核检查期间、比较基期、主体、增长/下降及“所有”等范围表述，并可继续读取财报。研究结论必须关联连续原文及来源；代码检查引文实际存在于已下载正文中，缺失、伪造或被判定矛盾的证据会阻断。原文存在不等于逻辑上必然支持结论，语义判定仍有模型局限。用户摘录和搜索片段可引导查找，但不会直接获得财报原文核验状态。

`01_evidence_review.json` 保存初始研究、检索片段、复核结果和逐项检查/撤回记录。详情页“查看结论与原文证据”可查看引文。缺口和局限由复核重新判断，不能仅通过修改旧报告状态绕过校验。

撰写数字校验会一次列出所有无法核验的数字及原因。两次模型改写仍失败时，系统保守撤回含无法核验数字的整句及其解释，保留该句中的已知引用和其他合规句子（包括已通过核验的数值）；不会直接删除数字、转成中文数字或虚构定性解释。撤回后的草稿再次按相同规则检查，报告“数据缺口”和页面“分析局限”披露这一处理。`03_writing_validation.json` 保存原句、替代说明及所有尝试，重试会追加记录。其他模型、网络或结构化输出错误仍按原有方式报错。历史失败任务可点击“从失败阶段重试”，复用已完成的研究与财务分析，无须重新补证据。

财务期间按原始事实的起止日期与申报财年对齐；比较期不直接使用所在申报的 `fy/fp` 作为自身期间。营收标签按期间合并选择，季度必须连续，缺失季度不会用更早年份的第四季度替代。自由现金流使用对应期间的经营现金流减购置支出；当使用包含软件及无形资产的 productive-assets 标签时，公式会明确披露这一口径。无法解析不等同于未披露，缺口会要求核对数据标签、期间及原始财报。
